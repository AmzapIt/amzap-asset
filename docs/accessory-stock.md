# Accessories: คลังกลางทั้งบริษัท

## การใช้งาน

- เมนู **Accessories / Stock** แสดงยอดพร้อมเบิกในคลัง ยอดที่พนักงานถือ และยอดตัดออก แยกตามประเภท/ยี่ห้อ/รุ่น/Serial ค้นหารายการและดูผู้ถืออยู่ได้
- **รับเข้า** เลือกรายการเดิมหรือสร้างรายการใหม่ กรอกจำนวน วันที่ ที่มาและหมายเหตุ การรับเข้าจะเพิ่ม Stock พร้อมเบิก
- **เบิกให้พนักงาน** จากหน้า Stock หรือส่วน Accessories ในหน้าพนักงาน เลือกของที่มี Stock และพนักงาน Active ระบบหักจากคลังและเพิ่มรายการที่ถืออยู่
- **แก้ไข** ในหน้าพนักงานแก้จำนวนที่ถืออยู่ วันที่เบิก หมายเหตุ หรือเลือก Stock ที่ถูกต้อง ส่วนต่างคืน/เบิกจากคลังอัตโนมัติ ต้องระบุเหตุผล ถ้ามีประวัติคืน/โอน/ตัดออกแล้ว เปลี่ยนชนิด Stock โดยคืนส่วนที่เหลือและเบิกใหม่
- **แก้ไขข้อมูล Stock** แก้ประเภท ยี่ห้อ รุ่น Serial ของรายการและรายการที่กำลังถืออยู่ที่เชื่อมกัน เก็บข้อมูลก่อน/หลังแก้ไข รายการที่ปิดแล้วคงข้อมูลเดิม
- **โอนบางส่วน / ทั้งหมด** เลือกพนักงานผู้รับ จำนวน วันที่และเหตุผล ลดจำนวนของผู้โอนและสร้างรายการของผู้รับ ยอดในคลังไม่เปลี่ยน
- **คืนบางส่วน / ทั้งหมด** เลือกจำนวนที่คืน ระบบเพิ่มยอดในคลังเฉพาะจำนวนนี้และแสดงจำนวนที่ยังถืออยู่ เมื่อเหลือ 0 รายการจะปิด
- **ตัดออก** ทำได้จากของในคลังและของที่พนักงานถืออยู่ เช่น เสีย สูญหาย เสื่อมสภาพ หรืออื่นๆ ต้องระบุเหตุผล การตัดออกจากพนักงานไม่เพิ่มของเสียกลับเข้าคลัง
- ประวัติแสดงวันที่ จำนวน ผลต่อคลัง ผู้โอน/รับ เหตุผล หมายเหตุ และผู้บันทึก โหลดประวัติเก่าเพิ่มได้ครั้งละ 100 รายการ
- Admin และ IT Staff บันทึกได้ Read-only ดูได้ พนักงาน Inactive รับเบิกใหม่หรือรับโอนไม่ได้ แต่คืน/โอนออก/ตัดออกได้

รายการที่มี Serial รับครั้งละ 1 ชิ้น และรับ Serial เดิมซ้ำขณะมีของในคลังหรือมีผู้ถืออยู่ไม่ได้ ของที่ไม่มี Serial รวม Stock เมื่อประเภท ยี่ห้อ รุ่นและ Serial ตรงกัน โดยไม่แยกตัวพิมพ์เล็ก/ใหญ่

## ฐานข้อมูลและการอัปเดต

ใช้ `migrations/019-accessory-stock.sql` หลังจากมีโครงสร้าง Accessories เดิม (`app/migrations/008-employee-accessories.sql`) และ `app_accounts` แล้ว Migration ทำงานใน Transaction และรันซ้ำได้

- เก็บ ID, จำนวน, วันที่ และข้อมูลเดิมใน `employee_accessories`
- เพิ่ม `accessory_stock_items` สำหรับยอดคลังกลาง และเชื่อมรายการเดิมตามประเภท/ยี่ห้อ/รุ่น/Serial
- ยอดเปิดนับเฉพาะของที่พนักงานกำลังถืออยู่ ของที่เคยคืนในอดีตไม่ได้ถูกสมมติว่ายังอยู่ในคลัง
- **ยอดพร้อมเบิกเริ่มที่ 0** ให้ตรวจนับของในคลังจริงแล้วบันทึกรับเข้าด้วยเหตุผล “ยอดจากตรวจนับเริ่มต้น”
- เพิ่ม counters คืน/โอน/ตัดออกในรายการพนักงาน ทำให้คืนบางส่วนได้ และรายงานใบรับมอบ/หน้า Dashboard ใช้ยอดที่ยังถืออยู่
- `accessory_stock_movements` เก็บประวัติ `opening`, `receive`, `issue`, `return`, `transfer`, `dispose`, `edit`
- `accessory_operations` เก็บ Request ID และผลลัพธ์สำหรับการส่งซ้ำจากการกดบันทึกซ้ำหรือเครือข่ายขัดข้อง

ยอดและประวัติบันทึกใน Transaction เดียวกัน ใช้ Advisory Lock ของคลังกลาง, Row Lock, เวอร์ชันของรายการ และ Constraint ป้องกันยอดติดลบ Request ID เดิมที่มีข้อมูลต่างกันถูกปฏิเสธ

## API

ทุก Endpoint ต้องเข้าสู่ระบบ บัญชี Active และเปลี่ยนรหัสผ่านบังคับแล้ว การเขียนต้องเป็น Admin/IT Staff

| Endpoint | หน้าที่ |
| --- | --- |
| GET `/api/accessories` | Stock, ผู้ถือ, ประเภท, พนักงาน Active และประวัติล่าสุด |
| POST `/api/accessories` | รับเข้ารายการเดิม/ใหม่ |
| PATCH `/api/accessories/[stockId]` | แก้ข้อมูล Stock |
| POST `/api/accessories/[stockId]/dispose` | ตัดออกจากคลัง |
| GET `/api/accessories/movements` | ประวัติ รองรับ `stock_id`, `user_id`, `before` |
| GET/POST `/api/users/[id]/accessories` | อ่านรายการพนักงาน / เบิกจากคลัง |
| PATCH `/api/users/[id]/accessories/[accessoryId]` | แก้รายการที่ยังถืออยู่ |
| PATCH `.../[accessoryId]/return` | คืนบางส่วน/ทั้งหมด |
| POST `.../[accessoryId]/transfer` | โอนบางส่วน/ทั้งหมด |
| POST `.../[accessoryId]/dispose` | ตัดออกจากของที่พนักงานถือ |

Mutation ต้องส่ง `request_id` (UUID v4) ถ้าแก้/คืน/โอน/ตัดออกต้องส่ง `expected_version` ของรายการล่าสุดด้วย จำนวนเป็นจำนวนเต็ม 1–100,000 วันที่เป็น `YYYY-MM-DD` และไม่เกินวันปัจจุบันในประเทศไทย
