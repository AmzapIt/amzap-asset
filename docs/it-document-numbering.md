# หลักเกณฑ์รหัสเอกสาร IT และเลขใบตรวจทรัพย์สิน

เอกสารนี้กำหนดรูปแบบรหัสสำหรับงานทรัพย์สิน IT ของ AMZAP เพื่อให้แยก **รหัสแบบฟอร์ม** ออกจาก **เลขที่เอกสารที่กรอกแล้ว** และค้นย้อนหลังได้ตรงกันทั้งฉบับพิมพ์และข้อมูลในระบบ

> สถานะ: ระบบมีโค้ดออกเลข `AV` อัตโนมัติและบันทึกใบตรวจแล้วในเมนู **รายงาน → ตรวจยืนยันทรัพย์สินประจำรอบ** แต่ต้องใช้ migration `029-asset-verifications.sql` กับฐานข้อมูลที่ต้องการใช้งานก่อนเปิดหน้า และต้องตรวจสอบว่า `FM-IT-001` และ `FM-IT-002` ไม่ซ้ำกับรหัสเอกสารที่องค์กรใช้อยู่

## ประเภทเอกสาร

| รหัสนำหน้า | ความหมาย | ตัวอย่างงาน IT |
| --- | --- | --- |
| `POL` | Policy — นโยบาย | นโยบายการใช้งาน IT |
| `PR` | Procedure — ขั้นตอนปฏิบัติ | ขั้นตอนจัดการสิทธิ์ผู้ใช้งาน |
| `WI` | Work Instruction — คู่มือปฏิบัติงาน | คู่มือการตั้งค่า Notebook |
| `FM` | Form — แบบฟอร์ม | ใบรับมอบทรัพย์สิน |
| `REG` | Register — ทะเบียน | ทะเบียนทรัพย์สิน IT (กรณีจัดทำเป็นเอกสารทะเบียนแยก) |
| `STD` | Standard — มาตรฐาน | มาตรฐานการตั้งรหัสผ่าน |

รหัสประเภทด้านบนเป็นหมวดของเอกสาร ไม่ใช่เลข Asset Code และไม่ใช่เลขรายการตรวจรายคน

## รหัสแบบฟอร์ม

รูปแบบ: `FM-IT-NNN Rev.XX`

- `FM` = แบบฟอร์ม, `IT` = หน่วยงานเจ้าของแบบฟอร์ม, `NNN` = ลำดับแบบฟอร์มสามหลัก, `Rev.XX` = ครั้งที่แก้ไขแม่แบบสองหลัก เริ่ม `Rev.00`
- `FM-IT-001` = ใบรับมอบทรัพย์สิน (แบบฟอร์มเดิม)
- `FM-IT-002 Rev.00` = ใบตรวจยืนยันทรัพย์สินประจำรอบ (แบบฟอร์มที่จะจัดทำ)
- หากแก้เนื้อหาหรือรูปแบบที่มีผลต่อการใช้งาน ให้ออก `Rev.01`, `Rev.02` ต่อไป โดย **ไม่เปลี่ยน** รหัส `FM-IT-002`
- ก่อนประกาศใช้ ให้ผู้ดูแลทะเบียนเอกสารตรวจว่าลำดับ `001` และ `002` ยังว่าง หากมีรหัสเดิมแล้ว ให้เลือกลำดับที่ว่างและอัปเดตเอกสารนี้ก่อนใช้งาน

แบบฟอร์มหนึ่งรหัสใช้พิมพ์ได้หลายใบ; `Rev` บอกเวอร์ชันของแม่แบบ ไม่ใช่จำนวนครั้งที่พิมพ์หรือจำนวนครั้งที่ตรวจ

## เลขใบตรวจยืนยันทรัพย์สินรายคน

รูปแบบ: `AV-YYYY-RR-NNNN`

| ส่วน | ความหมาย | ใน `AV-2026-01-0001` |
| --- | --- | --- |
| `AV` | Asset Verification — การตรวจยืนยันทรัพย์สิน | ใบตรวจยืนยัน ไม่ใช่ใบส่งมอบหรือทะเบียน Asset |
| `YYYY` | ปี ค.ศ. ของรอบตรวจ | `2026` |
| `RR` | ลำดับรอบตรวจในปีนั้น เริ่ม `01` | รอบแรกของปี = `01` |
| `NNNN` | ลำดับใบตรวจภายในรอบนั้น เริ่ม `0001` | ใบแรกของรอบ = `0001` |

ตัวอย่าง: `AV-2026-01-0001` คือใบตรวจรายคนลำดับแรกของรอบที่ 1 ปี 2026; `AV-2026-02-0001` คือใบแรกของรอบที่ 2 ปีเดียวกัน ใช้ปี ค.ศ. ในรหัสเสมอ แม้วันที่บนเอกสารจะแสดงแบบไทย

กติกาการใช้งาน:

1. กำหนดรอบตรวจให้ชัดก่อนออกเลข เช่น `2026-01` และ `2026-02` หากตรวจปีละสองรอบ
2. ออกเลข `NNNN` ถัดไปเมื่อสร้างใบตรวจของพนักงานในรอบนั้นเป็นครั้งแรก และเก็บเลขนั้นกับรายการตรวจ ไม่ออกเลขจากลำดับที่แสดงบนหน้าจอหรือจากการพิมพ์ PDF เฉย ๆ
3. พนักงานหนึ่งคนมีใบตรวจหลักหนึ่งเลขต่อรอบ; พิมพ์ซ้ำใช้เลขเดิม และระบุว่าเป็นสำเนา/พิมพ์ซ้ำหากต้องการติดตาม
4. เลขที่ยกเลิกห้ามนำกลับมาใช้ ให้บันทึกสถานะยกเลิกและเหตุผลไว้เพื่อไม่ให้ลำดับขาดโดยอธิบายไม่ได้
5. ไม่ใส่ Employee Code หรือชื่อพนักงานในเลขเอกสาร เพราะข้อมูลบุคคลอาจเปลี่ยน แต่เก็บรหัส/ชื่อพนักงานเป็นข้อมูลของใบตรวจแยกต่างหาก
6. เมื่อตรวจจริง ให้เก็บรายการ Asset และ Accessories ณ วันที่ตรวจ, วันที่ตรวจ, ผู้ตรวจ IT, ผู้ถือครอง และลายเซ็นพนักงานในฉบับที่ลงนาม การตรวจยืนยันไม่ใช่การเปลี่ยน Assignment หรือบันทึกการรับมอบใหม่
7. หากต้องแก้ใบที่ลงนามแล้ว ให้เก็บฉบับเดิมไว้ และกำหนดวิธีแก้ไข/ออกฉบับใหม่อย่างมีประวัติ ไม่เขียนทับหลักฐานเดิม

## ตัวอย่างบนใบตรวจ

```text
ใบตรวจยืนยันทรัพย์สินประจำรอบ
รหัสแบบฟอร์ม: FM-IT-002 Rev.00
เลขที่ใบตรวจ: AV-2026-01-0001
รอบตรวจ: 1/2026
พนักงาน: [ชื่อและรหัสพนักงาน]
วันที่ตรวจ: [วันที่ตรวจจริง]
รายการที่ตรวจ: [Asset และ Accessories]
ลงชื่อ: [พนักงาน]  [ผู้ตรวจ IT]
```

`FM-IT-001` ใช้กับใบรับมอบเดิมเท่านั้น; ไม่ใช้เลข `AV-...` แทนเลขใบรับมอบ หากภายหลังต้องกำหนดเลขรายการใบรับมอบ ให้กำหนดชุดเลขของใบรับมอบแยกต่างหากก่อนพัฒนา

## วิธีใช้ในระบบ

1. เปิดเมนู **รายงาน → ตรวจยืนยันทรัพย์สินประจำรอบ** แล้วสร้างรอบตรวจด้วยปี ค.ศ., ลำดับรอบ และชื่อรอบ
2. ตรวจรายชื่อพนักงาน Active ทุกคน รวมคนที่ไม่มีทรัพย์สิน กดดูรายการ Asset/Accessories ก่อนออกใบ โดยเฉพาะรายการที่แสดง **Owner เดิม** ซึ่งต้องตรวจรายชิ้น
3. กด **ออกใบตรวจ** ระบบอ่านข้อมูลปัจจุบันจากฐานข้อมูล เก็บ snapshot รายการพนักงาน/อุปกรณ์ และออกเลข `AV` จากลำดับของรอบนั้น เลขจะไม่ซ้ำเมื่อออกพร้อมกันหลายเครื่อง
4. กด **ดู / พิมพ์ซ้ำ** เพื่อเปิด PDF จาก snapshot เดิม เลข `AV` ไม่เปลี่ยน การพิมพ์ซ้ำไม่สร้างใบใหม่
5. หลังได้รับกระดาษที่พนักงานและ IT เซ็นแล้ว ระบุวันที่รับใบ ผลตรวจว่าตรง/ไม่ตรง และรายละเอียดหากไม่ตรง จากนั้นกด **รับเอกสารที่เซ็นแล้ว** สถานะนี้เป็นบันทึกการรับเอกสาร ไม่ใช่ลายเซ็นอิเล็กทรอนิกส์
6. หากออกใบผิดก่อนรับเอกสารที่เซ็น สามารถยกเลิกพร้อมเหตุผล ใบและเลขเดิมยังอยู่ในประวัติ แล้วจึงออกใบใหม่ หากรับเอกสารที่เซ็นแล้ว ระบบไม่อนุญาตให้ยกเลิกจากหน้านี้

การออกและรับใบตรวจ **ไม่เปลี่ยน Assignment, Asset Owner หรือยอด Accessory Stock** กรณีรายการไม่ตรง ต้องตรวจและแก้ข้อมูลหลักผ่านกระบวนการ Asset/Accessory ที่เกี่ยวข้อง ไม่แก้ snapshot ของใบที่ออกไปแล้ว

## การเปิดใช้งานและงานที่ยังแยกต่างหาก

- รัน `migrations/029-asset-verifications.sql` กับฐานข้อมูลที่ต้องการใช้ก่อนเข้าเมนู; โปรเจกต์ไม่รัน migration อัตโนมัติเมื่อ build หรือเปิดเว็บ
- ตรวจสอบรหัส `FM-IT-001/002` กับทะเบียนเอกสารจริง และกำหนดผู้รับผิดชอบอนุมัติ/ควบคุม Revision ก่อนประกาศใช้อย่างเป็นทางการ
- ยังไม่มีการอัปโหลดไฟล์สแกนกระดาษที่เซ็นแล้ว หรือการลงลายเซ็นออนไลน์ ต้องเก็บฉบับกระดาษตามวิธีควบคุมเอกสารขององค์กร
